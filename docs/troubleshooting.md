# 실행 오류와 제약사항

| 증상 | 확인 및 조치 |
|---|---|
| Docker Engine 파이프 또는 daemon 연결 실패 | Docker Desktop 또는 Docker Engine을 실행하고 `docker info`에서 Server가 응답하는지 확인한다. 엔진이 없는 Windows에서는 README의 로컬 실행 절차를 사용한다. |
| 데이터 연결 오류 | 로컬 통합 실행에서는 8130 포트, 개발 분리 실행에서는 8000 포트의 `/api/health`를 열어 status를 확인한다. 분리 실행 시 Vite의 API_TARGET과 백엔드 주소를 맞춘다. |
| Python·npm 설치 실패 | Python 3.12, uv, Node.js 22, npm과 첫 설치의 네트워크 연결을 확인한다. Windows 임시 디렉터리 접근 거부 시 쓸 수 있는 경로를 TEMP와 TMP에 지정하고 재시도한다. |
| 업로드가 413 또는 422로 거부됨 | UTF-8 또는 CP949 CSV인지, 크기 4 MiB·5만 행·64열 이내인지, 지표 열과 각 행의 열 수가 맞는지 확인한다. 허용 열 이름은 사용자 설명서에 있다. |
| 실행 실패 또는 결과 없음 | 시스템 로그에서 실행 ID와 실패 단계를 확인한다. 외부 모델 모드는 서버의 키·모델명·연결 상태를 점검한다. 현금 제약을 충족하는 일정이 없을 때는 입력값을 재검토한다. |
| 특정 차트가 비어 있음 | 현재 선택한 자료에 해당 지표가 있는지 확인한다. 당도와 출하량은 각각 전용 자료를 선택해야 한다. |

로컬 시연은 단일 서버 프로세스를 전제로 한다. 서버 재시작으로 중단된 실행은 실패 상태에서 같은 조건으로 다시 요청할 수 있다. [사용자 매뉴얼](user_manual.md) · [설치·의존성·환경변수](../README.md)
