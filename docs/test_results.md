# 실행 및 검증 결과

검증 환경은 Windows, Python 3.12.13, 로컬 SQLite 및 별도 PostgreSQL 18.6 인스턴스다. 테스트용 입력과 시연 거래는 사용자 가정이다. 프로젝트의 공식 관측 자료와 별도로 취급한다.

|검증 대상|실행 방법|관찰 결과|
|---|---|---|
|백엔드 회귀 테스트|backend에서 python -m pytest -q|20개 통과. CP949/BOM 업로드, 잘못된 구조, 전체 결측, 집계, 음수·0일 보관·소량 경계, OR-Tools와 작은 재고의 완전탐색 해 비교, 현금 조건, 감사 로그, PDF·CSV 검증.|
|프론트엔드 테스트|frontend에서 npm test|Vitest 4개 통과. 입력 검증·실행, 서버 오류, 비교와 다운로드, CSV 탐색 화면.|
|정적 검사·빌드|ruff check app tests alembic / npm run build|Ruff 검사 통과. TypeScript 검사 및 Vite 프로덕션 빌드 성공. Recharts 포함 번들 크기 안내가 출력됨.|

|PDF 렌더링|다운로드 응답을 pdftoppm -r 100 -png로 렌더|한글 폰트·5개 전략 표·순수입 차트·출처·일정을 1페이지에서 확인.|

### 시연 수치 재현

1,000kg, 현재 2,000원/kg, 10일 후 2,400원/kg, 일일 보관비 3원/kg, 회당 출하비 20,000원, 최소 당일 순현금 400,000원, 균형형으로 실행했다.

|안|예상 순수입(원)|당일 순현금(원)|현금 조건|
|---|---:|---:|---|
|즉시 전량|1,980,000|1,980,000|충족|
|2회 분할|2,145,000|980,000|충족|
|3회 분할|2,124,815|648,000|충족|
|보관 후 출하|2,350,000|0|미충족|
|선호 반영 최적화|2,252,300|400,000|충족|

최적 배분은 당일 210kg, 10일차 790kg이다. 당일 순현금은 210×2,000−20,000=400,000원이다. 전체 출하비 40,000원과 보관비 23,700원이 반영된다. 미래 단가의 ±10% 민감도는 같은 배분을 유지한 상태에서 다시 계산한다.

### 확인한 경고

OR-Tools의 SWIG 타입에 대한 Python 폐기 예정 경고, pandas의 결측 대체 시 형변환 변경 안내, React Router의 차기 버전 안내가 있었다. 테스트 종료 상태는 성공이다.

PostgreSQL 18.6에서 실제 출하 요청도 별도로 제출했다. 도구 호출 10건과 보고서가 저장됐으며, 최적 배분 순수입 2,252,300원 및 당일 순현금 400,000원이 SQLite 결과와 일치했다.
